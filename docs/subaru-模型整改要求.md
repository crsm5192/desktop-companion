# subaru 模型与桌宠软件整改要求

适用对象：`models/subaru`。

本要求以 2026-11-06 首次诊断时的导出文件为基准。后续修改过的模型应按验收清单重新检查，文中的“当前幅度”记录首次诊断值。

本要求依据导出模型、动作曲线、Cubism Core 网格变形和桌宠真实窗口测试制定。已确认资源完整、参数绑定有效。重点是恢复软件参数控制、提高小尺寸下的表情辨识度，并明确动作叠加规则。

以下数值属于第一轮调参建议，需在 Cubism 原工程中验证。角度参数的数值不等于已测得的视觉旋转角度；最终以实际变形、人物风格和桌宠显示效果验收。

## 2. 模型参数与变形整改

### 2.1 嘴型

涉及参数：`ParamMouthForm`、`ParamMouthOpenY`。

涉及部件：`ArtMeshMouth`、`ArtMeshMouth_lip_0`、`ArtMeshMouth_lip_1`、`ArtMeshToothT`、`ArtMeshTongue`。

整改要求：

1. 保留 `ParamMouthForm=-1～1`、默认 0。建立 -1、0、1 的明确形态：下弯嘴、自然嘴、上扬嘴。
2. 目前微笑已使用 `ParamMouthForm=1`，达到参数上限。提高微笑辨识度应修改端点变形，而不是把 JSON 数值改为 2。
3. 以中性嘴宽 W 为尺度，第一轮可把嘴角相对中性的垂直变化设为 W 的 10%～20%，结合角色风格调整。
4. `ParamMouthOpenY=0` 必须闭合；建议增加 0、0.25、0.5、0.75、1 的开合关键形态，变化连续。
5. 完成嘴型与开口的组合检查：MouthForm 的 -1、0、1 分别配合 MouthOpenY 的 0、0.5、1，共 9 组。
6. 张嘴时，上下唇、牙齿、舌头、口腔遮罩须同步；闭嘴时不得露牙、漏出舌头或出现黑缝。

验收：相同头部姿势下，闭嘴微笑与悲伤应能在实际桌宠尺寸下直接区分；说话时仍保留嘴角情绪。

### 2.2 眉毛与情绪区分

涉及参数：`ParamBrowLY`、`ParamBrowRY`；涉及部件：`ArtMeshEyebrowL`、`ArtMeshEyebrowR`。

目前眉毛最大变形约为原画布的 2～3 像素，缩小后差异较弱；悲伤和生气都主要使用眉毛整体下移。

整改要求：

1. 保留左右眉独立控制，默认 0，范围 -1～1。
2. 第一轮可将上下移动的端点幅度调整至中性眼睛高度 H 的 20%～35%，避免被刘海完全遮住。
3. 增加眉毛倾斜或形状控制，例如 `ParamBrowLAngle`、`ParamBrowRAngle`，默认 0、范围 -1～1；必须在原工程建立实际绑定。
4. 悲伤应表现为眉头抬高、眉尾降低；生气应表现为眉头压低并向内收。两者须形成不同轮廓。
5. 新参数的正负方向须按左右眉分别记录，不能假定左右参数使用同一符号就能形成对称倾斜。
6. 检查眉毛极值、头部转动和眼睛开合组合，避免眉毛越出面部、穿入眼睛或与刘海异常交叠。

验收：隐藏表情名称，只看同一姿势的面部，能够区分悲伤与生气。

### 2.3 眼睛与眨眼兼容

涉及参数：`ParamEyeLOpen`、`ParamEyeROpen`、`ParamEyeBallX`、`ParamEyeBallY`、`ParamEyeBallForm`。

整改要求：

1. 左右眼开合保留 0～1。0 为完全闭合，1 为正常睁眼，左右眼可独立闭合。
2. 微笑、悲伤、生气的开合系数可继续使用 Multiply；眨眼到 0 时，乘法结果仍为 0。
3. 当前惊讶表情使用 Overwrite 把 EyeOpen 固定为 1，会覆盖此前执行的闭眼值。应改成可兼容眨眼的方案，例如 Multiply=1，并由独立眼型参数表现惊讶。
4. 如新增 `ParamEyeLForm` / `ParamEyeRForm`，需在原工程定义中性、眯眼、惊讶眼型，并验证每种眼型都能正常闭合。新增 JSON ID 本身不会产生变形。
5. 眼球 X/Y 的 ±1 端点必须保持虹膜处于有效眼白遮罩内；不得露出眼眶或出现明显穿帮。
6. 四个表情分别测试双眼眨眼、左眼眨眼、右眼眨眼。

验收：惊讶保持时仍能闭眼；Wink 只闭合目标眼睛；微笑不通过长时间接近闭眼冒充笑眼。

### 2.4 头部与身体

整改要求：

1. 保留现有参数 ID 与范围，优先修改有效变形。`ParamAngleX` 范围为 -45～45，Y/Z 为 -30～30；身体角度和前后倾范围为 -10～10。
2. 头部 X 端点应表现左右转头，Y 端点应表现抬头和低头；根据美术需求调整鼻子、眼睛、耳朵和面部轮廓的相对位置。
3. 检查 X/Y 的四个角点及过渡，防止组合转头时五官位置失真。
4. 头部与颈部连接连续；头饰与头部联动，前后发允许延迟跟随。
5. 身体前后倾、身体转动和头部低头应有区别，不能全部表现为人物整体平移。
6. 点头、鞠躬、身体摆动时检查脚底位置，避免人物在地面滑动。
7. 除非制作目标明确需要，动作不要驱动 `ParamProportion`，以免头身比例在普通动作中变化。

验收：在人物显示高度约 350～600 像素时，点头、摇头和鞠躬的方向可辨认；在参数极值下无断颈、面部裂缝或网格翻折。

## 3. 四个表情文件整改

共同要求：每个表情明确设定嘴角、左右眉、眼型及新增情绪参数；无意使用的情绪参数须回到中性。保留约 0.3～0.5 秒的淡入淡出。

| 表情 | 参数起点 | 必须呈现的视觉差异 |
| --- | --- | --- |
| 微笑 | MouthForm=1；EyeOpen Multiply=0.75～0.9；BrowY=0.2～0.4 | 嘴角上扬、眼睛柔和，不能只有眼皮下降 |
| 悲伤 | MouthForm=-0.8～-1；EyeOpen Multiply=0.8～0.9；眉形呈眉头高、眉尾低 | 与生气明显不同的眉形和下弯嘴 |
| 生气 | MouthForm=-0.4～-0.7；EyeOpen Multiply=0.75～0.9；眉形呈眉头低、向内收 | 眉间压迫感明显，不能只整体降低眉毛 |
| 惊讶 | MouthForm=0；MouthOpenY=0.6～0.8；BrowY=0.7～1；独立惊讶眼型 | 抬眉、眼型变化和张嘴同时可见，仍兼容眨眼 |

眉毛倾斜参数的具体值须根据新绑定确定，以上不预设左右眉的符号。

涉及文件：`school-clean.smile.exp3.json`、`school-clean.sad.exp3.json`、`school-clean.angry.exp3.json`、`school-clean.surprised.exp3.json`。

## 4. 动作曲线整改

先完成有效变形，再调整动作幅度。下面均为第一轮参数建议，不要求机械采用最大值。

| 动作 | 当前主要幅度 | 第一轮调整要求 |
| --- | --- | --- |
| Nod | AngleY 约 -4～1；BodyAngleY 约 -0.6～0 | AngleY 低头峰值 -12～-18；BodyAngleY -2～-3；先低头、再柔和回正 |
| Shake | AngleX 约 ±5；EyeBallX 约 ±0.25 | AngleX ±12～18；EyeBallX ±0.3～0.6；左右交替 2～3 次，最后回正 |
| Blink | EyeOpen 0～1 | 保留完整闭合；一次眨眼本体约 0.15～0.3 秒；区分动作总时长与闭眼持续时间 |
| Wink | 左 EyeOpen 0～1；AngleZ 约 -2.2 | 左眼完整闭合，右眼保持自然睁开；轻歪头约 3～6，避免双眼同时关闭 |
| LookAround | AngleX 约 ±4.5；EyeBallX 约 ±0.58 | AngleX ±10～15；眼球先行，头部延后约 0.1～0.2 秒，左右短暂停留 |
| Curious | AngleZ 约 3.4；EyeBallY 约 0.3 | 歪头约 6～10；结合单眉抬起与目光上移，保持片刻后回正 |
| Happy | AngleY 约 ±1.74；BodyAngleY 约 ±0.52 | 头部约 ±3～6、身体约 ±1～2；配合明确微笑，呈轻快节奏 |
| Shy | AngleY 约 -2.5；AngleZ 约 -2；横向视线约 -0.4 | 低头 -5～-8、歪头约 3～6；回避视线，节奏柔和；脸红为可选扩展 |
| Sleepy | AngleY 约 -4.2；眼睛有闭合 | 缓慢低头约 -5～-10；眼皮逐渐下落，停留后恢复，避免重复急眨眼 |
| Bow | AngleY 约 -5；BodyAngleY 约 -1.2；BodyLean 约 -0.8 | 头部 -15～-22、身体 -3～-5、前倾 -2～-4；脚底稳定，与 Nod 明显区分 |
| Sway | AngleZ 约 ±0.58；BodyAngleX 约 ±1.17 | 头部约 ±2～3、身体约 ±2～3；缓慢左右交替，身体与头部略有错峰 |
| Talk | MouthOpenY 0～0.8 | 保留开口幅度；保持停顿和闭口帧；头部只做轻微陪衬 |
| TalkHappy | MouthOpenY 0～1；MouthForm 0～0.8 | 保留开口幅度，确保嘴角微笑实际可见；与普通 Talk 区分 |
| TalkSoft | MouthOpenY 0～0.5；MouthForm -0.3～0 | 保留较小开口、更多停顿与柔和节奏，不扩大成普通 Talk |

动作时序要求：

1. 主动作必须出现可辨识的峰值；峰值附近通常可停留约 0.15～0.35 秒，按动作风格调整。
2. 每次动作结束应回到明确的基准姿态或由软件平滑衔接，不能留下半张嘴、斜头或偏移身体。
3. 默认淡入淡出约 0.3～0.5 秒可保留，但 Blink 等短动作须单独调整，防止淡入淡出吞掉闭眼峰值。
4. 无意控制的参数不要批量写入常量曲线；用于恢复姿态的常量曲线可以保留，并注明用途。
5. 不强制把全部 Idle 改为 Loop=true。目前 8 个 Idle 为非循环文件，由软件随机续播；修改循环策略时须保证仍能切换不同 Idle。
6. 相邻 Idle 的首尾姿势应平滑衔接；普通待机不应持续大幅转头或频繁张嘴。

## 5. 软件侧控制要求

### 5.1 保留已完成的修复

- 非语音、非互动状态释放嘴型，不固定写 0。
- 模型动作播放期间，视线追踪让出头部与眼球参数；结束后恢复。
- 手动动作允许替换当前动作；API 控制与复位能够释放覆盖。
- 语音播放期间，音频口型优先于表情和动画的张嘴参数；语音结束后恢复模型的正常控制。

### 5.2 处理默认呼吸与模型动作叠加

框架默认呼吸会给头部 X/Y/Z 额外叠加约 ±7.5、±4、±5，给 BodyAngleX 叠加约 ±2。当前 Nod 的低头峰值约 -4，与默认 Y 摆动同量级，因此仅恢复参数控制仍可能产生视觉干扰。

整改要求：

1. 播放 Nod、Shake、Bow 等主动作时，降低或关闭默认呼吸中的头部、身体角度通道，保留 `ParamBreath` 的胸腹呼吸。
2. 对已包含完整待机摆动的模型，避免重复叠加框架头部摆动。
3. 第一轮可将额外摆动控制在主动作峰值的 20% 以内；进入和退出采用约 0.2～0.4 秒的平滑过渡。
4. 验证点头过程中不会因额外摆动出现先抬头、方向抵消或节奏失真。

### 5.3 明确动作时长与参数优先级

当前 API `motion.play` 未指定时长时默认约 3.5 秒，而模型 LookAround 为 5.4 秒、Talk 为 8 秒、TalkHappy 为 6 秒、TalkSoft 为 7 秒。

整改要求：

1. 非循环动作默认按文件完整时长播放；调用方显式指定 durationMs 时，按指定时长平滑结束。
2. 循环动作应有明确停止规则，不套用非循环动作的结束逻辑。
3. 不同参数分别确定所有权：语音优先控制张嘴；持久手动表情控制嘴角、眉形；眨眼与情绪眼型能够组合；模型动作控制其需要的头部与视线。
4. 手动表情与 TalkHappy 的嘴角产生冲突时，行为必须一致并有明确规则，例如持久手动表情继续保留，清除它后再由动作控制嘴角。
5. 临时表情结束恢复此前的持久表情；新动作、取消、模型切换和异常都应清理临时覆盖。
6. 动作是否生效必须同时检查参数轨迹与画面/网格变化，不能只判断按钮被点击或请求返回成功。

## 6. 工程、导出与交付要求

交付原 `.cmo3` 工程、可编辑美术源文件及其必要资源；只有 `.moc3` 无法按本要求直接修改变形绑定。

模型制作完成后重新导出并交付：

- `school-clean.moc3`
- `school-clean.model3.json`
- `school-clean.cdi3.json`
- `school-clean.physics3.json`
- 纹理目录及 `texture_00.png`
- 4 个 `.exp3.json`
- 22 个 `.motion3.json`，或明确记录增删项
- 参数说明表：ID、含义、范围、默认值、正负方向、受影响部件
- 同姿势的中性与四个表情对比图，以及动作演示录像

导出检查要求：

1. 现有参数 ID 保持兼容；新增参数须同时出现在实际 moc 绑定、参数说明和使用它的表情/动作中。
2. model3 的资源路径均存在并使用相对路径，避免依赖制作者电脑的绝对路径。
3. EyeBlink 组保留左右眼开合；LipSync 组保留 `ParamMouthOpenY`。
4. 新增表情、动作须完成 model3 声明；即使软件可自动发现，也应提供完整导出配置。
5. 动作元信息计数与实际曲线一致；无需为放大效果提高纹理分辨率或渲染分辨率。

## 7. 验收清单

使用相同模型比例、相同头部姿势与相同背景对比。至少检查人物实际显示高度 350、450、600 像素，覆盖浅色和深色背景。

- [ ] 中性、微笑、悲伤、生气、惊讶可区分，尤其悲伤与生气不能只靠说明文字区分。
- [ ] MouthForm 的 -1、0、1 与 MouthOpenY 的 0、0.5、1 共 9 组组合无穿帮。
- [ ] 四个表情分别能完整双眼眨眼、左眼眨眼、右眼眨眼；惊讶不会强制睁眼。
- [ ] Nod、Shake、Bow 的方向、节奏和幅度有明显区别；脚底无明显滑动。
- [ ] 头部 X/Y 角点组合及眼球极值下无五官错位、破面和遮罩溢出。
- [ ] 开启/关闭视线追踪时，手动动作和 API 动作均正常；结束后追踪恢复。
- [ ] Talk 8 秒、TalkHappy 6 秒、TalkSoft 7 秒及 LookAround 5.4 秒默认能完整播放。
- [ ] 语音静音片段嘴巴闭合，有声音时张嘴；语音结束恢复表情。
- [ ] 连续切换四个表情、重复动作、取消动作、模型切换后无残留覆盖。
- [ ] Idle 连续运行至少 10 分钟，切换平滑，无重复大幅摆动、嘴型漂移或物理抖动。
- [ ] 修复纳入安装包后，在安装版中重新验证以上关键场景。

先完成 P0 软件落地，再处理 P1 的嘴角、眉形、眼型和主动作。P2 的新增手臂、脸红等能力不作为现有四个表情整改的前置条件。
