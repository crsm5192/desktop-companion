# 安和昴桌宠 · 常驻后台语音服务

> 本文档整理「安和昴陪伴（desktop-companion）」桌宠所用**常驻后台语音服务**的建立过程与使用方法。
> 该服务基于 CosyVoice3（安和昴 LoRA 音色克隆）常驻内存，提供 HTTP / 流式合成接口，桌宠与 hermes-agent **共用同一份模型**。
>
> 文档核对时间：2026-09-07（此时服务正在运行，监听 `0.0.0.0:8001`，安装方式为「启动文件夹 .vbs」）。

---

## 0. 一句话概述

桌宠说话依赖 CosyVoice3。每说一句都冷启动一次 Python 会很慢，所以做成了一个**常驻后台的 HTTP 服务**：

- 只启动一次，模型常驻内存（`/health` 返回 ok）；
- 桌宠把「日语：」行发到 `POST /tts` 得到 `audio/wav` 直接播放；
- 语言自动判断（含假名=日语，否则中文），中日音色一致；
- 默认 **CPU 常驻**（约 6 GB 内存），说话那几秒搬上 GPU（约 2~3 GB 显存），空闲 60 秒自动退回 CPU，把显存还给 ComfyUI。

> 本服务**只合成，不训练**。LoRA 是之前训练好的，训练过程（CosyVoice3 部署坑、Kaldi 数据、全量 vs LoRA、中文混合比例实验、日转片假名修正）见 `语音克隆完整记录.md`。

### 3.2 服务脚本的核心设计（`subaru_tts_server.py`）

1. **LoRA 手动注入**：CosyVoice3 内部是 Qwen2 LLM，用 peft 会破坏访问路径，因此手写 `LoRALinear`（r=16, α=32）注入到每层 attention 的 `q_proj/k_proj/v_proj/o_proj`，再 `load_state_dict` 热切换两份 LoRA（`zh`/`jp`）。
2. **双语言自动路由**：文本含假名（`[\u3040-\u30ff]`）→ 日语走 `inference_cross_lingual`（先 `ja_katakana.py` 转片假名并修正助词 は→ワ/へ→エ/を→オ）；否则中文走 `inference_zero_shot`（长文本 `torch.cat` 拼多 chunk）。
3. **auto 设备管理**：`--device auto` 时模型常驻 CPU（占内存约 6 GB，保证中日两份 LoRA 常驻以快速热切换），说话时 `to("cuda")` 搬上 GPU，一个 5 秒的 watcher 线程检查 `--gpu-idle-seconds`（默认 60 秒）空闲后自动退回 CPU，把显存还给 ComfyUI。
4. **纯标准库 HTTP**：`ThreadingHTTPServer` + `BaseHTTPRequestHandler`，无框架依赖；并发请求用 `threading.Lock` 串行化模型推理。
5. **无窗口后台适配**：用 `pythonw.exe` 跑时 `sys.stdout` 为 `None`，脚本自动把 stdout/stderr 重定向到 `subaru_tts_server.log`，避免 print 崩溃。
6. **跨进程共用**：`--host 0.0.0.0` 让工位机/笔记本局域网都能访问，桌宠和 hermes 共用同一份模型。

### 3.3 命令行参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--port` | `8001` | 监听端口 |
| `--host` | `0.0.0.0` | 监听地址；本机用 `127.0.0.1`，局域网用 `0.0.0.0` |
| `--device` | `auto` | `auto`=CPU常驻/用时搬GPU；`cpu`=纯CPU；`cuda`=一直留GPU |
| `--gpu-idle-seconds` | `60` | 空闲多少秒后退回 CPU；`0`=一直留 GPU |

### 3.4 部署为「常驻后台」——两种方式

有**两套并存**的安装脚本，效果都是开机自启 + 无窗口后台，选一种即可：

**方式 A：启动文件夹 VBS（当前实际生效方式 ✅）**
- 安装：`D:\workspace\cosyvoice\install_tts_service.bat`
  1. 杀掉残留的 `subaru_tts_server` 进程；
  2. 把 `subaru_tts_startup.vbs` **复制**到 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\`；
  3. 立即用 `wscript.exe` 启动。
- VBS 内容：用 `pythonw.exe` 静默跑 `subaru_tts_server.py --host 0.0.0.0 --port 8001 --device auto`（`sh.Run(..., 0, False)` 参数 0 = 隐藏窗口）。
- 卸载：`uninstall_tts_service.bat`（杀进程 + 删除启动文件夹里的 vbs）。

**方式 B：计划任务 SubaruTTS**
- 安装：`powershell -ExecutionPolicy Bypass -File D:\workspace\cosyvoice\install_tts_service.ps1`
  - 注册任务名 `SubaruTTS`：`pythonw.exe subaru_tts_server.py --host 0.0.0.0 --port 8001 --device auto`，登录时（`AtLogOn`）触发，允许用电池、失败 1 分钟后重启至多 3 次、无执行时长限制；注册后立即 `Start-ScheduledTask`。
- 卸载：`uninstall_tts_service.ps1`（`Unregister-ScheduledTask SubaruTTS`）。
- ⚠️ 2026-09-07核对时此任务**未安装**（`schtasks /query /tn SubaruTTS` 不存在），生效的是方式 A。

**桌宠里的启动模板**（`desktop-companion\scripts\start-tts-server.bat`）只是一份参考脚本，注意其中 `cd /d D:\path\to\cosyvoice` 是**占位路径**，要用时改成你的真实目录；它的注释也点出 `--device cpu` 会触发 CosyVoice3 CPU 推理 bug（kernel size 报错），故用 `auto`。

## 4. 使用篇（怎么调用）

### 4.1 桌宠端使用（默认就该这么用）

桌宠在**服务器模式**下访问常驻服务：

**配置**（`config.json`，开发时在 `%APPDATA%\DesktopCompanion\config.json`；便携版在 exe 旁；NSIS 在 `%APPDATA%\DesktopCompanion\`）：

```json
{
  "tts": {
    "mode": "server",
    "server": { "baseUrl": "http://127.0.0.1:8001", "voice": "subaru" },
    "lang": "auto",
    "speed": 1.0,
    "timeoutMs": 300000
  }
}
```

设置面板（⚙️）→「TTS（安和昴 / CosyVoice）」：
- **模式**：`server（常驻服务，推荐）` 或 `command（每句 CLI，备用）`；
- 选 server 时填 **Base URL**（默认 `http://127.0.0.1:8001`）；
- 选 command 时才需要填 `python` 路径、`subaru_voice.py` 脚本路径、`cwd`、`lang`；
- **测试按钮**：点击会合成并播放「测试语音，你好，我是安和昴。」（首次 10~30 秒加载模型）。

**一次说话的完整链路**：
1. 对话：人设 `chat.persona` + 语音规则 `chat.voiceRule`（要求模型在回复最后单独写一行「日语：」开头的日语口语版）；
2. 前端 `parseAssistantReply` 提取「日语：」行（没有标签则自动找含假名的连续段落）作为 `speak` 文本，中文去掉 🎧/路径/「翻译：」等元数据作为 `display`；
3. `useTTS.speak` → `window.api.tts.speak`（IPC `tts:speak`）；
4. 主进程 `synthesize`（server 模式）`fetch POST {baseUrl}/tts`，body `{text, lang, speed}`；
5. 拿到 `audio/wav` 的 base64 → 渲染层 `new Audio('data:audio/wav;base64,...')` 播放；
6. 播放期间 `useSpeechStore` 驱动 `mouthLevel`（多正弦叠加，最高约 3Hz）写入 Live2D `ParamMouthOpenY`，实现**口型联动**；播完归零；
7. 同一句合成结果会按文本缓存（最多 30 条），点小喇叭直接重播不再重新生成。

### 4.2 直接 HTTP 调用

```bash
# 健康检查
curl http://127.0.0.1:8001/health

# 合成语音（桌宠 /tts，返回 wav）
curl -X POST http://127.0.0.1:8001/tts \
  -H "Content-Type: application/json" \
  -d '{"text":"こんにちは、昴です！","lang":"auto","speed":1.0}' \
  -o out.wav

# OpenAI 兼容（hermes 用，默认返回 mp3）
curl -X POST http://127.0.0.1:8001/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{"input":"你好，我是安和昴","voice":"subaru","response_format":"mp3"}' \
  -o out.mp3
```

局域网访问：桌宠/笔记本把 `baseUrl` 改成 `http://<工位机IP>:8001`（服务需 `--host 0.0.0.0`，且 Windows 防火墙放行 8001 端口；该服务**无鉴权**，仅限可信内网）。

### 4.3 hermes-agent 接入（共用同一份模型）

- **command 模式**（桌宠 `tts.mode="command"`）：主进程 `spawn(cfg.python, ['-u', subaru_voice.py, input.txt, output.wav, lang, speed])`，每句冷启动、文件进/文件出，作为 server 模式不可用时的兜底。

## 5. API 参考

### GET `/health`
返回 `{"ok": true, "device": "cpu|cuda", "current_lang": "zh|jp"}`。用于服务是否存活、当前在 CPU 还是 GPU。

### POST `/tts`（桌宠用）
请求：
```json
{ "text": "...", "lang": "auto|zh|jp", "speed": 1.0 }
```
- `text` 必填；`lang` 默认 `auto`（按是否含假名自动判定）；`speed` 默认 `1.0`。
返回：`200 audio/wav`（原始 PCM WAV 字节）。

### POST `/v1/audio/speech`（OpenAI 兼容 / hermes 用）
请求：
```json
{ "input": "...", "voice": "zh|jp|其它", "response_format": "mp3|wav" }
```
- `voice`：`zh`/`jp` 强制语言，其它任意值（如 `subaru`）→ `auto`；
- `response_format`：默认 `mp3`（经 ffmpeg 转 `libmp3lame 192k`），否则返回 wav。
返回：`200 audio/mpeg` 或 `audio/wav`。

## 5.5 hermes 切换到常驻服务（2026-09-07 已完成）

- hermes 实际配置 `C:\Users\duyun\AppData\Local\hermes\config.yaml` 的 `tts:` 段写法（正确版）：
  ```yaml
  tts:
    provider: openai
    openai:
      base_url: http://127.0.0.1:8001/v1
      api_key: sk-local
      model: subaru
      voice: subaru
  ```
- ⚠️ **关键**：hermes 内置 openai TTS provider 读的是**顶层 `tts.openai.base_url`**（不是 `tts.providers.openai`）。
  若把 base_url/apikey 放错层级，`provider: openai` 会走默认 OpenAI 端点而非本服务（认证失败/指向别处）。
  放对后可用 `hermes config get tts` 确认 `base_url` 指向 8001。
- 改完用 `hermes gateway restart` 重启网关生效。
- hermes 语音工具名是 **`text_to_speech`**（不是 `tts`），调用带 `voice: subaru` → 命中 8001 的 `/v1/audio/speech`。
- **落盘位置**：调用不传 `output_path` 时，默认写到 `%LOCALAPPDATA%\hermes\cache\audio\tts_<时间戳>.mp3`
  （`get_hermes_dir("cache/audio")`）。agent 可传 `output_path` 指定任意路径；默认目录可能因权限被拒
  （Errno 13），让 agent 改存工作区即可。

## 6. 排障与注意

| 现象 | 处理 |
|---|---|
| `/health` 失败 | 服务没起 → 跑 `install_tts_service.bat` 或手动前台启动；`netstat -ano | findstr 8001` 看端口 |
| 端口 8001 被占 | 换 `--port` 并同步改桌宠 `tts.server.baseUrl` |
| 首次说话要 10~30 秒 | 正常：首次启动就在加载模型，之后常驻就快了 |
| `--device cpu` 报 kernel size 错误 | CosyVoice3 CPU 推理 bug，改用 `auto`（先 CPU 常驻、说话才上 GPU） |
| 低语速(speed<1)报 kernel size 错误 | hifigan 独立子模型曾留在 CPU；服务端 `to_gpu()` 已改为分别搬 `llm`+`flow`+`hift` 三个子模型 |
| 长文本/特定文本报 `padded input size (3) < kernel (4)` | 分块推理出现 0 帧尾块；已给 `CosyVoice\cosyvoice\transformer\convolution.py` 的 `CausalConv1d.forward` 打补丁（不足 kernel 时右端补零，输出裁回原帧数） |
| 高倍速(≥5x)短文本报 `output (W: 0)` | `token2wav` 里 `F.interpolate(size=int(shape[2]/speed))` 把 mel 缩到 0 帧；已钳到至少 1 帧（`model.py` 补丁） |

### 音色相似度的度量边界（重要）

campplus 嵌入下，**同一说话人不同语句的自然相似度仅 0.730**（0.602~0.831），合成 0.714 已达自然变化的 98%；自参考（拿原句当参考）上限 0.849。**95% 超出该度量的物理区间**——它衡量的是"与某一次特定录音的匹配度"，不是"是不是这个人"。
